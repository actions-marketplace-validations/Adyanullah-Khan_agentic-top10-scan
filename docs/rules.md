# Rules

Rule IDs are this project's own. The `ASIxx` part names the primary category of the [OWASP Top 10 for Agentic Applications](https://genai.owasp.org/); secondary categories are listed per rule. Generated by `agentic-top10 rules --format markdown`.

## ASI01 Agent Goal Hijack

**Checked statically:** Untrusted web/document/tool content flowing into prompts (taint tracking), user input in system prompts, prompt-injection phrases and invisible Unicode in prompts, instruction files and tool descriptions, exfiltration channels, untrusted GitHub event text fed to CI agents.

**Not visible to static analysis:** Whether the model actually resists an injection at runtime. Red-team the running agent (e.g. garak, promptfoo, PyRIT) and add runtime input/output guardrails.

### ATS-ASI01-01

**Untrusted content flows into an LLM prompt without delimiting** · default severity `high` · categories ASI01, ASI06

Web pages, documents, search results, retrieved chunks or tool output reach a system prompt or chat message as raw text. Instructions hidden in that content can take over the agent's goal.

**Fix:** Wrap untrusted content in clear delimiters (e.g. <untrusted_document>...</untrusted_document>), tell the model it is data not instructions, keep it out of the system prompt, and filter it with an injection classifier before use.

### ATS-ASI01-02

**User-controlled input is interpolated into a system prompt** · default severity `high` · categories ASI01

Request data or model-chosen tool arguments are formatted into the system/developer prompt, giving users the same authority as the developer.

**Fix:** Keep the system prompt static. Pass user input only as a user-role message.

### ATS-ASI01-03

**Prompt-injection or tool-poisoning text in prompts, instructions or tool descriptions** · default severity `high` · categories ASI01

Phrases such as 'ignore previous instructions', chat-template control tokens, or hidden directives inside tool descriptions (tool poisoning) were found in text the model will read.

**Fix:** Remove the text. Review where it came from; treat third-party prompt files, rules files and MCP tool descriptions as untrusted code.

### ATS-ASI01-04

**Invisible or bidirectional Unicode characters** · default severity `high` · categories ASI01, ASI04

Zero-width, bidi-override or Unicode tag characters can hide instructions from human reviewers while the model still reads them (ASCII smuggling / Trojan Source).

**Fix:** Delete the characters (the evidence shows their code points and any decoded hidden text). Add a pre-commit check that rejects them.

### ATS-ASI01-05

**Data-exfiltration channel in a prompt or instruction** · default severity `medium` · categories ASI01

Templated markdown images/links or instructions to send conversation data to a URL let an attacker who hijacks the agent leak data through rendered output or tool calls.

**Fix:** Do not render model-produced images/links from untrusted domains; strip URLs with dynamic query strings; allowlist outbound domains.

### ATS-ASI01-06

**Untrusted GitHub event text is interpolated into an AI agent workflow** · default severity `critical` · categories ASI01, ASI03

Issue/PR/comment titles or bodies are inserted with ${{ }} into an AI agent's prompt or a run step, so anyone who can open an issue can steer an agent that holds repository credentials.

**Fix:** Pass event text through environment variables, never ${{ }} interpolation; restrict who can trigger the agent; give the job read-only permissions.

### ATS-ASI01-07

**AI agent workflow can be triggered by any GitHub user** · default severity `low` · categories ASI01, ASI03

The agent runs on issue/comment/PR-target events with no check on the author's association or permission, so outsiders can feed it instructions.

**Fix:** Add an if: condition on github.event.comment.author_association (OWNER/MEMBER/COLLABORATOR) or check the actor's permission before running the agent.

## ASI02 Tool Misuse and Exploitation

**Checked statically:** Agent tools that run shell commands, write/delete files, fetch model-chosen URLs or build SQL from model input; dangerous built-in toolkits; wildcard tool permissions; disabled TLS.

**Not visible to static analysis:** How tools are chained at runtime and whether runtime argument validation holds up.

### ATS-ASI02-01

**Agent tool executes operating-system commands** · default severity `high` · categories ASI02, ASI05

A function exposed to the model as a tool runs shell or OS commands. A hijacked or confused agent can run arbitrary commands with the agent's privileges.

**Fix:** Replace generic command execution with narrow, purpose-built tools; never pass model-chosen strings to a shell; run tools in a sandbox and require approval for anything destructive.

### ATS-ASI02-02

**Agent tool accesses the file system with a model-controlled path** · default severity `high` · categories ASI02

A tool opens, writes, moves or deletes a path taken from model-chosen arguments without confining it to an allowed directory (path traversal).

**Fix:** Resolve the path and verify it stays inside an allowed root (Path.resolve().is_relative_to(root)); make destructive operations require approval.

### ATS-ASI02-03

**Agent tool fetches a model-controlled URL (SSRF)** · default severity `medium` · categories ASI02, ASI01

A tool sends HTTP requests to a URL chosen by the model or a user, which can reach internal services, cloud metadata endpoints, or exfiltrate data.

**Fix:** Allowlist schemes and hosts, block private/link-local ranges, and do not forward credentials.

### ATS-ASI02-04

**SQL built from model or user input** · default severity `high` · categories ASI02, ASI05

A query string is assembled from model output, tool arguments or request data, enabling SQL injection or destructive queries chosen by the model.

**Fix:** Use parameterised queries, a read-only database role, and an allowlist of query shapes.

### ATS-ASI02-05

**Dangerous built-in agent tool or toolkit enabled** · default severity `high` · categories ASI02, ASI05

Shell, Python REPL, unrestricted HTTP or file-management toolkits give the model general-purpose capabilities far beyond what most tasks need.

**Fix:** Remove the toolkit or replace it with narrow custom tools; if unavoidable, sandbox it and restrict it to a root directory / allowlisted hosts.

### ATS-ASI02-06

**TLS certificate verification disabled** · default severity `medium` · categories ASI02, ASI07

Tool or agent traffic accepts any certificate, so a network attacker can read or alter tool results and inter-agent messages.

**Fix:** Remove verify=False / rejectUnauthorized:false; pin a CA bundle if you use private certificates.

### ATS-ASI02-07

**Tool granted wildcard or admin permissions** · default severity `high` · categories ASI02, ASI03

A tool in the agent manifest has '*', admin or write-all permissions, violating least privilege.

**Fix:** List the exact scopes the tool needs.

## ASI03 Identity and Privilege Abuse

**Checked statically:** Hardcoded credentials, secrets placed into prompts, over-scoped CI tokens for agents, LLM keys exposed to browsers, unauthenticated endpoints, privileged containers, unrestricted delegation.

**Not visible to static analysis:** Real IAM policies, cloud role scopes and token lifetimes, and runtime confused-deputy behaviour.

### ATS-ASI03-01

**Hardcoded credential** · default severity `high` · categories ASI03, ASI04

A secret is committed to the repository. Agents that read the repository (or attackers who steal it) inherit the credential.

**Fix:** Revoke and rotate the secret, then load it from a secret manager or environment variable.

### ATS-ASI03-02

**Secret placed into an LLM prompt or context** · default severity `high` · categories ASI03, ASI01

An API key, password or token is inserted into text sent to the model, where prompt injection or logging can leak it.

**Fix:** Keep credentials in tool code only; the model should never see them.

### ATS-ASI03-03

**AI agent workflow runs with broad repository permissions** · default severity `medium` · categories ASI03

An AI agent job has write-all or high-impact write scopes (or no explicit permissions), so a hijacked agent can push code, change workflows or mint cloud credentials.

**Fix:** Declare minimal permissions per job (contents: read; add pull-requests: write only if needed).

### ATS-ASI03-04

**LLM API key exposed to the browser** · default severity `high` · categories ASI03

The client is configured to run in the browser or the key is in a public build-time variable, so any visitor can extract and abuse it.

**Fix:** Call the model from a server route; never ship provider keys to the client.

### ATS-ASI03-05

**Agent endpoint or tool declared without authentication** · default severity `high` · categories ASI03, ASI07

A remote endpoint the agent calls or exposes is declared with auth: none.

**Fix:** Require OAuth2, mTLS or scoped API keys for every remote endpoint.

### ATS-ASI03-06

**Privileged container or host access for the agent runtime** · default severity `high` · categories ASI03, ASI05

The agent or one of its MCP servers runs privileged, mounts the Docker socket or host root, or shares the host network/PID namespace, so code execution becomes host compromise.

**Fix:** Run as a non-root user without --privileged, host mounts or the Docker socket; drop capabilities.

### ATS-ASI03-07

**Unrestricted agent delegation** · default severity `low` · categories ASI03, ASI02

Agents may delegate work to any other agent, which can launder privileges through a more powerful agent (confused deputy).

**Fix:** Restrict delegation to named agents and propagate the original caller's permissions.

## ASI04 Agentic Supply Chain Vulnerabilities

**Checked statically:** Unpinned MCP servers, actions and agent dependencies, remote code/model loading, dynamic imports, auto-trusted project MCP servers, known-vulnerable packages (opt-in OSV lookup).

**Not visible to static analysis:** Publisher integrity, malicious packages that look clean, and tool descriptions that change after install (MCP rug pulls). Use signed/pinned artifacts and an allowlist.

### ATS-ASI04-01

**MCP server or agent tool launched from an unpinned package** · default severity `medium` · categories ASI04

npx/uvx/docker launches fetch whatever version is newest at runtime, so a compromised release is executed automatically with the agent's access.

**Fix:** Pin an exact version (pkg@1.2.3, pkg==1.2.3) or an image digest, and review upgrades.

### ATS-ASI04-02

**Remote code, model or prompt loaded at runtime** · default severity `high` · categories ASI04, ASI05

trust_remote_code, pickle-based model files, unpinned prompt-hub pulls, curl|sh launches or exec of downloaded content run code you have not reviewed.

**Fix:** Vendor and pin reviewed artifacts; use safetensors; pin hub pulls to a commit hash.

### ATS-ASI04-03

**Agent framework dependency is not pinned** · default severity `low` · categories ASI04

An LLM/agent framework dependency floats to new versions and no lockfile was found.

**Fix:** Pin exact versions or commit a lockfile, and update deliberately.

### ATS-ASI04-04

**GitHub Action not pinned to a commit SHA** · default severity `low` · categories ASI04

A third-party action is referenced by a mutable tag or branch, which its owner (or an attacker) can repoint. Severity is raised for workflows that run AI agents.

**Fix:** Pin to a full 40-character commit SHA and let Dependabot update it.

### ATS-ASI04-05

**Dependency with a known vulnerability** · default severity `high` · categories ASI04

OSV reports a published advisory for this exact package version (only checked with --online).

**Fix:** Upgrade to a fixed version.

### ATS-ASI04-06

**Module imported from a dynamic name** · default severity `medium` · categories ASI04, ASI05

importlib/__import__ with a non-literal name lets configuration, users or the model choose which code is loaded.

**Fix:** Map allowed plugin names to modules explicitly.

### ATS-ASI04-07

**Project MCP servers or agent extensions are auto-trusted** · default severity `medium` · categories ASI04, ASI09

Settings automatically enable every MCP server defined in the repository, so a malicious pull request can add a server that runs on the next agent session.

**Fix:** Approve MCP servers individually.

## ASI05 Unexpected Code Execution (RCE)

**Checked statically:** eval/exec, LLM output reaching exec/shell/SQL, shell=True, unsandboxed code executors (AutoGen, CrewAI, smolagents, LangChain, Open Interpreter), unsafe deserialization.

**Not visible to static analysis:** How strong your sandbox really is (container escape, network egress).

### ATS-ASI05-01

**Dynamic code evaluation** · default severity `high` · categories ASI05

eval/exec/compile (or JavaScript eval/new Function/vm) runs a non-literal string.

**Fix:** Remove dynamic evaluation; use ast.literal_eval/JSON parsing or an explicit dispatch table.

### ATS-ASI05-02

**LLM output reaches code, command or query execution** · default severity `critical` · categories ASI05, ASI01

Text produced by a model is executed. Anyone who can influence the model's input (including indirect prompt injection) gets code execution.

**Fix:** Never execute model output directly. If code execution is the feature, run it in an isolated sandbox (container/VM with no secrets or network) and require approval.

### ATS-ASI05-03

**Shell command execution** · default severity `high` · categories ASI05

shell=True, os.system, os.popen or child_process.exec with string interpolation enables command injection.

**Fix:** Pass an argument list without a shell, validate inputs, or use a library API instead.

### ATS-ASI05-04

**Agent code execution is not sandboxed** · default severity `high` · categories ASI05

The agent framework is configured to run model-written code directly on the host (AutoGen without Docker, CrewAI unsafe mode, smolagents local executor with broad imports, LangChain allow_dangerous_code, PAL chains).

**Fix:** Use a container/VM/remote sandbox executor, restrict imports, and remove secrets from the environment.

### ATS-ASI05-05

**Unsafe deserialization** · default severity `high` · categories ASI05, ASI06

pickle/marshal/dill/unsafe YAML loading runs code embedded in the data; loaded memories, vector stores or messages become an execution vector.

**Fix:** Use JSON or yaml.safe_load; never deserialize pickles from untrusted locations.

## ASI06 Memory and Context Poisoning

**Checked statically:** Untrusted content written to long-term memory or vector stores without validation, memory objects shared across users, retrieval without tenant filters, declared memory policy.

**Not visible to static analysis:** Content already sitting in your vector DB and poisoning of external knowledge bases.

### ATS-ASI06-01

**Untrusted content written to long-term memory without validation** · default severity `medium` · categories ASI06

User input, tool arguments or fetched content is stored in a vector store or persistent memory with no validation step, so a single poisoned item influences future sessions and other users.

**Fix:** Validate/classify content before storing it, record provenance, separate trusted and untrusted memory, and expire entries.

### ATS-ASI06-02

**Agent memory shared across users or sessions** · default severity `medium` · categories ASI06, ASI03

A memory object is created once at module level in a web service, or memory is read/written without a user/session identifier, so one user's (poisoned) context leaks into another's.

**Fix:** Create memory per session and scope every read/write by user_id/session_id/tenant.

### ATS-ASI06-03

**Retrieval in a request handler without a tenant filter** · default severity `low` · categories ASI06

A vector search inside a request handler has no metadata filter or namespace, so users can retrieve (or be steered by) other tenants' documents.

**Fix:** Filter every retrieval by tenant/user metadata or use per-tenant namespaces.

### ATS-ASI06-04

**Declared persistent memory lacks isolation, validation or expiry** · default severity `medium` · categories ASI06

The agent manifest declares persistent memory that is shared, unvalidated or never expires.

**Fix:** Set scope: per_user (or per_session), write_validation: true and a ttl.

## ASI07 Insecure Inter-Agent Communication

**Checked statically:** Plaintext HTTP for agent/MCP/A2A links, A2A agent cards without security schemes, unauthenticated agent endpoints, agent services bound to all interfaces, declared channel auth.

**Not visible to static analysis:** Runtime message integrity, replay protection and protocol downgrade.

### ATS-ASI07-01

**Agent, MCP or A2A link over plaintext HTTP** · default severity `medium` · categories ASI07

Messages between agents or to tool servers travel unencrypted to a non-local host, so they can be read or altered in transit.

**Fix:** Use https:// (TLS 1.2+), ideally with mutual TLS between agents.

### ATS-ASI07-02

**A2A agent card declares no authentication** · default severity `high` · categories ASI07, ASI03

The published agent card has no securitySchemes/security, so any client can call the agent and peers cannot verify each other.

**Fix:** Declare securitySchemes (OAuth2/OIDC, mTLS or API key) and require them on every skill.

### ATS-ASI07-03

**Agent invocation endpoint without authentication** · default severity `medium` · categories ASI07, ASI03

A web route runs an agent or LLM call with no visible authentication dependency, decorator or header check, so anyone can drive the agent and spend its privileges.

**Fix:** Require authentication (e.g. FastAPI Depends(verify_user), @login_required) on agent routes.

### ATS-ASI07-04

**Agent service listens on all network interfaces** · default severity `low` · categories ASI07

An agent/MCP server binds to 0.0.0.0, exposing it beyond the local machine.

**Fix:** Bind to 127.0.0.1 unless remote access is intended, and put authentication in front of it.

### ATS-ASI07-05

**Declared inter-agent channel lacks authentication or integrity** · default severity `medium` · categories ASI07

The manifest declares agent-to-agent communication with no auth, plaintext transport or unsigned messages.

**Fix:** Use mTLS or OAuth2 between agents and sign messages.

## ASI08 Cascading Failures

**Checked statically:** Missing iteration/turn limits, infinite loops around LLM calls, network calls without timeouts, unbounded retries, silently swallowed tool errors, declared limits.

**Not visible to static analysis:** Real fan-out and blast radius, rate limiting and circuit breakers in infrastructure.

### ATS-ASI08-01

**Agent loop has no iteration or turn limit** · default severity `medium` · categories ASI08

An agent loop is unbounded (None/very large iteration limit, or while True around LLM calls with no exit), so errors and injected goals can run away and spread.

**Fix:** Set explicit max iterations/turns, a wall-clock timeout and a cost budget.

### ATS-ASI08-02

**Network call without a timeout** · default severity `low` · categories ASI08

A tool or LLM client can hang indefinitely, stalling the agent and everything waiting on it.

**Fix:** Pass an explicit timeout to every outbound call.

### ATS-ASI08-03

**Unbounded retries** · default severity `medium` · categories ASI08

A retry decorator has no stop condition, so a failing dependency is hammered forever and failures amplify across agents.

**Fix:** Add stop_after_attempt/max_tries and exponential backoff with jitter.

### ATS-ASI08-04

**Tool or agent-loop errors silently swallowed** · default severity `low` · categories ASI08, ASI10

Exceptions in a tool or agent loop are caught and ignored, hiding failures that then cascade downstream.

**Fix:** Log the error and return an explicit failure result to the agent.

### ATS-ASI08-05

**Declared agent has no execution limits** · default severity `low` · categories ASI08

An agent in the manifest has no max_iterations / max_runtime limit.

**Fix:** Declare limits for iterations, runtime and cost.

## ASI09 Human-Agent Trust Exploitation

**Checked statically:** High-impact tools without human approval, approval-bypass settings and CLI flags, prompts telling the agent to deceive users or never ask for confirmation.

**Not visible to static analysis:** UI design that over-trusts agent output and user over-reliance.

### ATS-ASI09-01

**High-impact tool runs without human approval** · default severity `high` · categories ASI09, ASI02

A tool that sends messages, moves money, deletes data or deploys code has no confirmation or interrupt step, so a manipulated agent acts with the user's trust.

**Fix:** Add a human-in-the-loop approval (e.g. LangGraph interrupt, needs_approval, an explicit confirm step) for irreversible actions.

### ATS-ASI09-02

**Human approval disabled or bypassed** · default severity `high` · categories ASI09, ASI05

Settings or flags auto-approve agent actions (bypassPermissions, --dangerously-skip-permissions, alwaysAllow, auto_run, require_approval: never, human_input_mode NEVER with code execution).

**Fix:** Keep approval on for writes, shell and network tools; scope auto-approval to read-only tools.

### ATS-ASI09-03

**Prompt instructs the agent to deceive or manipulate users** · default severity `medium` · categories ASI09

The prompt tells the agent to hide that it is an AI, pretend to be human, hide risks or pressure the user, which exploits user trust.

**Fix:** Remove deceptive instructions; disclose AI involvement and uncertainty.

### ATS-ASI09-04

**Prompt instructs the agent to act without confirmation** · default severity `medium` · categories ASI09

The prompt tells the agent never to ask for confirmation or permission.

**Fix:** Instruct the agent to confirm irreversible or high-impact actions with the user.

### ATS-ASI09-05

**Declared high-risk tool does not require approval** · default severity `high` · categories ASI09, ASI02

A tool with write/delete/payment/shell/send capabilities is declared without requires_approval: true.

**Fix:** Set requires_approval: true for the tool.

## ASI10 Rogue Agents

**Checked statically:** Agents that can rewrite their own code, prompts or permissions, persistence mechanisms, runtime package installs, tools with no audit logging or tracing, declared kill switch.

**Not visible to static analysis:** Behavioural drift, collusion and goal misalignment. These need runtime monitoring.

### ATS-ASI10-01

**Agent can modify its own code, prompts or permissions** · default severity `high` · categories ASI10

A tool (or code acting on LLM output) writes to the agent's own source, prompt files, manifest or permission settings, letting a compromised agent entrench itself.

**Fix:** Make agent code, prompts and settings read-only to the agent; change them only through reviewed deployments.

### ATS-ASI10-02

**Persistence mechanism reachable from agent code** · default severity `high` · categories ASI10

Agent code can install cron jobs, services, launch agents, shell profile hooks, SSH keys or detach background processes, letting a rogue agent survive restarts.

**Fix:** Remove the capability; agents should not be able to schedule or daemonise processes.

### ATS-ASI10-03

**Agent tool installs packages at runtime** · default severity `medium` · categories ASI10, ASI04

A tool runs pip/npm/apt install, letting the agent expand its own capabilities with unreviewed code.

**Fix:** Bake dependencies into the image; deny package installation in the sandbox.

### ATS-ASI10-04

**Agent tool calls are not audit-logged** · default severity `low` · categories ASI10

Agent tools were found but none of them log their calls and no tracing library (LangSmith, Langfuse, OpenTelemetry, ...) is used, so rogue behaviour cannot be detected or investigated.

**Fix:** Log every tool call (who, what, arguments, result) or enable agent tracing.

### ATS-ASI10-05

**Declared agent system lacks a kill switch or audit log** · default severity `low` · categories ASI10

The manifest's oversight section does not declare a kill switch and audit logging.

**Fix:** Provide a way to halt agents immediately and record their actions; declare both in the manifest.
